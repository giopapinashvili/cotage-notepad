# აგარაკის ჯავშნები — ოჯახის საერთო რვეული

ქართულად შექმნილი, პაროლით დაცული ჯავშნების რვეული გიორგისთვის, დედასთვის, ვეკოსა და ლიკასთვის. ტელეფონზე შეგიძლია მთავარ ეკრანზე დააყენო და საკუთარი ხატულიდან გახსნა. როდესაც ერთ-ერთი წევრი წერს, ცვლილებები იმავე რვეულში შესულ დანარჩენ წევრებთანაც ჩნდება.

პროექტი განკუთვნილია **შენს Cloudflare ანგარიშზე გასაშვებად**. მასში ერთადაა გვერდის ფაილები, ავტორიზაცია, საერთო მონაცემების შენახვა და პირდაპირი სინქრონიზაცია. სერვერი იყენებს Cloudflare Worker-სა და SQLite Durable Object-ს; ცალკე მონაცემთა ბაზის ხელით შექმნა საჭირო არ არის.

## რა არის მზად

- თვეებით დალაგებული, გასაშლელი და ჩასაკეცი ჯავშნები.
- სტატუსები: „თავისუფალია“, „დაჯავშნილია“, „დადასტურებას ველოდებით“ და „ჩვენთვის დაკავებულია“.
- შესვლისა და გასვლის თარიღები და საათები, სტუმრების რაოდენობა, სრული ფასი, ავანსი, დარჩენილი თანხა, სტუმრის სახელი, ტელეფონი და დამატებითი ჩანაწერი.
- თითოეული ოჯახის წევრის პირადი პაროლი და დაკავშირებული წევრების გამოჩენა.
- წერისას ჩანაწერის გაზიარება, დაუმთავრებელი მონახაზები და საბოლოო შენახვა.
- გადამკვეთი ჯავშნების დაბლოკვა, გაუქმება და გაუქმებული ჯავშნის აღდგენა.
- ცვლილებების ისტორია, პაროლის შეცვლა და გიორგისთვის JSON სარეზერვო ასლის ჩამოტვირთვა.
- Android-სა და iPhone-ზე დასაყენებელი ვებაპი — PWA.

## 1. მოამზადე კომპიუტერი

დაგჭირდება [Node.js](https://nodejs.org/en/download) **22 ან უფრო ახალი ვერსია**, [Visual Studio Code](https://code.visualstudio.com/) და შენი Cloudflare ანგარიში. Node.js-ის დაყენების შემდეგ VS Code ხელახლა გახსენი, რათა ტერმინალმაც დაინახოს ახალი პროგრამა.

ZIP არქივი მთლიანად ამოიღე ცალკე საქაღალდეში, მაგალითად `cottage-notebook`. VS Code-ში აირჩიე **File → Open Folder** და გახსენი ის საქაღალდე, რომელშიც ერთად დევს `package.json`, `package-lock.json` და `wrangler.jsonc`.

გახსენი **Terminal → New Terminal**. ქვემოთ მოცემული ბრძანებები ამ ტერმინალში, პროექტის საქაღალდიდან, ცალ-ცალკე შეასრულე. კოდის ბლოკის წარწერა `bash` ბრძანების ნაწილი არ არის.

Node.js-ის ვერსიის შესამოწმებლად:

```bash
node --version
```

პასუხი უნდა იწყებოდეს `v22`-ით ან უფრო დიდი ვერსიის რიცხვით.

## 2. აირჩიე ამ რვეულის Cloudflare სახელი

გახსენი `wrangler.jsonc`. დასაწყისში ნახავ:

```json
"name": "agarakis-rveuli"
```

პირველ გაშვებამდე შეგიძლია შეცვალო, მაგალითად `giorgis-agarakis-rveuli`-ით. გამოიყენე პატარა ლათინური ასოები, ციფრები და დეფისი. **აირჩიე სახელი, რომელიც შენს თამაშს ან სხვა არსებულ Worker-ს არ ჰქვია**, რათა განთავსება სწორედ ამ ახალ რვეულს შეეხოს.

დანარჩენი კონფიგურაცია არსებული სახით დატოვე. `durable_objects` და `migrations` საერთო საცავს განსაზღვრავს. პირველი გაშვების შემდეგ Worker-ის სახელის ან საცავის იდენტობის შეცვლა ცალკე გადატანის სამუშაოა და ჩვეულებრივ განახლებას არ სჭირდება.

## 3. დააყენე საჭირო პროგრამები

```bash
npm ci
```

დაელოდე დასრულებას. პროექტში დაფიქსირებულია Wrangler-ის ვერსია **4.148.0**, ამიტომ ქვემოთ მოცემული ბრძანებები იმავე ვერსიით შესრულდება.

## 4. ერთხელ შექმენი საიდუმლო გასაღებები

```bash
npm run secrets
```

ბრძანება პროექტის საქაღალდეში შექმნის **`.dev.vars`** ფაილს. მასში იქნება ორი ავტომატურად გენერირებული მნიშვნელობა:

| სახელი | დანიშნულება |
| --- | --- |
| `APP_SECRET` | სერვერის მუდმივი საიდუმლო გასაღები. მომხმარებლების პაროლების შემოწმება მასზეა დამოკიდებული. |
| `SETUP_TOKEN` | რვეულის პირველი გამართვის ერთჯერადი კოდი, რომ ოჯახის ანგარიშების პაროლები მხოლოდ შენ დააყენო. |

ZIP-ში ნამდვილი `.dev.vars` არ არის — მას შენს კომპიუტერზე ეს ბრძანება ქმნის. `.dev.vars.example` მხოლოდ ფორმატის მაგალითია; იქ ჩაწერილი ტექსტები მოქმედი გასაღებები არ არის.

**შეინახე `.dev.vars` უსაფრთხო ადგილას. ფაილი, მისი შიგთავსი ან სქრინშოტი საჯაროდ არ განათავსო, Git-ში არ ატვირთო და `public` საქაღალდეში არ გადაიტანო.** პირველი განთავსების ბრძანება ამ მნიშვნელობებს შენს Cloudflare ანგარიშში დაცულ secrets-ად შეიტანს. იხილე [Cloudflare Secrets-ის ინსტრუქცია](https://developers.cloudflare.com/workers/configuration/secrets/).

თუ ბრძანება გეუბნება, რომ `.dev.vars` უკვე არსებობს, ის არსებულ ფაილს არ გადააწერს. გამოიყენე უკვე შექმნილი ფაილი.

**მოქმედ რვეულზე `APP_SECRET` იგივე უნდა დარჩეს.** ახალი მნიშვნელობის ჩასმა უკვე შექმნილი პაროლების შემოწმებას დააზიანებს. ჩვეულებრივი განახლებისას გასაღებების თავიდან გენერაცია საჭირო არ არის.

## 5. შედი შენს Cloudflare ანგარიშში

```bash
npx wrangler login
```

გაიხსნება ბრაუზერი. შედი იმ Cloudflare ანგარიშით, რომელზეც რვეულის განთავსება გინდა, და დაადასტურე Wrangler-ის ავტორიზაცია. რამდენიმე ანგარიშზე წვდომის შემთხვევაში აირჩიე შესაბამისი ანგარიში.

## 6. პირველად განათავსე რვეული ონლაინ

```bash
npx wrangler deploy --secrets-file .dev.vars
```

ეს ბრძანება ერთად განათავსებს გვერდის ფაილებსა და სერვერს, შექმნის კონფიგურაციაში აღწერილ საცავს და `.dev.vars`-ის მნიშვნელობებს Worker secrets-ად შეიტანს. `--secrets-file`-ით განთავსება აღწერილია [Cloudflare-ის ოფიციალურ ინსტრუქციაში](https://developers.cloudflare.com/workers/configuration/secrets/#upload-secrets-alongside-code).

დასრულებისას ტერმინალში გამოჩნდება შენი საიტის **HTTPS მისამართი**, რომელიც ჩვეულებრივ `workers.dev`-ით მთავრდება. გახსენი სწორედ ის მისამართი. თუ შენს ანგარიშს `workers.dev` ქვედომენი ჯერ არ აქვს, მიჰყევი Cloudflare-ის მიერ შემოთავაზებულ მის გამართვას.

`public` საქაღალდე ეკრანის ფაილებს შეიცავს; პაროლებს, შენახვასა და საერთო განახლებებს `src/worker.js` ამუშავებს. ამიტომ ონლაინ გასაშვებად გამოიყენე პროექტის სრული განთავსების ბრძანება.

## 7. პირველად დააყენე ოჯახის პაროლები

ახალ მისამართზე გამოჩნდება **„პირველი გამართვა“**.

1. VS Code-ში გახსენი შენი `.dev.vars`.
2. `SETUP_TOKEN=` ხაზიდან დააკოპირე **მხოლოდ `=` ნიშნის შემდეგ არსებული მნიშვნელობა**. `SETUP_TOKEN=` ტექსტი არ ჩასვა.
3. ეს მნიშვნელობა ჩასვი საიტზე „გამართვის კოდის“ ველში. `APP_SECRET` ამ ველში არ გამოიყენება.
4. ოთხივე წევრს შეურჩიე საკუთარი პაროლი. თითოეული უნდა იყოს **12–128 სიმბოლო**.
5. დაასრულე გამართვა და შემდეგ შედი შენი სახელითა და პაროლით.

| შესვლის ეკრანზე | შიდა მომხმარებლის სახელი | წვდომა |
| --- | --- | --- |
| გიორგი | `giorgi` | ყველა ჯავშანი, საკუთარი და ოჯახის სხვა წევრების პაროლის შეცვლა, სარეზერვო ასლის ჩამოტვირთვა |
| დედა | `deda` | ყველა ჯავშნის ნახვა და მართვა, საკუთარი პაროლის შეცვლა |
| ვეკო | `veko` | ყველა ჯავშნის ნახვა და მართვა, საკუთარი პაროლის შეცვლა |
| ლიკა | `lika` | ყველა ჯავშნის ნახვა და მართვა, საკუთარი პაროლის შეცვლა |

აპში სახელი ჩამონათვალიდან ირჩევა. მზა საერთო პაროლი არ არსებობს — პაროლებს ამ ეტაპზე შენ ადგენ. წარმატებული პირველი გამართვის შემდეგ გამართვის კოდი ანგარიშების თავიდან შესაქმნელად აღარ მუშაობს.

ოჯახის წევრებს მიეცი **ერთი და იგივე საიტის მისამართი**, თითოეულს — თავისი პაროლი. `.dev.vars` და გამართვის კოდი მათ აპის გამოყენებისთვის არ სჭირდებათ.

## 8. დააყენე ტელეფონებზე

ამ ნაბიჯს თითოეული ტელეფონისთვის ცალ-ცალკე შეასრულებთ. რვეული ვებაპის სახით იდგმება და საკუთარი ხატულით იხსნება. დასაყენებლად გამოიყენე უკვე გამოქვეყნებული HTTPS მისამართი.

### Android — Chrome

1. საბოლოო საიტის მისამართი გახსენი **Chrome-ში**.
2. გახსენი ბრაუზერის **⋮** მენიუ.
3. აირჩიე **Install app** ან **Add to Home screen**.
4. დაადასტურე დაყენება. ხატულიდან გახსენი რვეული და შედი შესაბამისი წევრის ანგარიშით.

აპის „დაყენება“ ღილაკიც გამოიყენება. თუ ავტომატური შეთავაზება არ გამოჩნდა, იმავე ეკრანზე იქნება ხელით დაყენების ინსტრუქცია. მენიუს ზუსტი წარწერა ბრაუზერსა და მის ვერსიაზეა დამოკიდებული. [PWA დაყენების ინსტრუქცია — MDN](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Installing).

### iPhone — Safari

1. საბოლოო საიტის მისამართი გახსენი **Safari-ში**.
2. დააჭირე **Share / გაზიარებას**.
3. აირჩიე **Add to Home Screen**.
4. თუ გამოჩნდა **Open as Web App**, ჩართე და დააჭირე **Add**.
5. მთავარ ეკრანზე დამატებული ხატულიდან გახსენი რვეული. საჭიროების შემთხვევაში ხელახლა შედი.

თუ Add to Home Screen სიაში არ ჩანს, Share-ის მოქმედებების ბოლოში მოძებნე **Edit Actions** და დაამატე. [Apple-ის ინსტრუქცია](https://support.apple.com/guide/iphone/bookmark-a-website-iph42ab2f3a7/ios).

თუ მისამართი პირველად Messenger-ის ან სხვა აპის შიდა ბრაუზერში გახსენი, დაყენებისთვის გადაიტანე Chrome-ში ან Safari-ში.

## ყოველდღიური გამოყენება

### ახალი ჯავშანი და თანხები

გახსენი თავისუფალი თარიღი და დააჭირე **„ჯავშნის დამატებას“**, ან გამოიყენე ეკრანის ქვედა ღილაკი. ერთი ჯავშნით შეგიძლია რამდენიმე დღე მოიცვა. ახალი ჩანაწერის საწყისი საათებია შესვლა 15:00-ზე და გასვლა შემდეგი დღის 12:00-ზე; თითოეულ ჯავშანში თარიღებისა და საათების შეცვლა შეგიძლია.

თანხები იწერება ლარებში. „სრული ფასი“ არის **მთელი ჯავშნის თანხა**; ღამეების რაოდენობაზე ფასი ავტომატურად არ მრავლდება. „დარჩენილი“ სრული ფასიდან ავანსის გამოკლებით გამოითვლება. მაგალითად, სრული ფასი 600 და ავანსი 200 ნიშნავს დარჩენილ 400 ლარს. ათწილადის საჭიროებისას გამოიყენე წერტილი, მაგალითად `250.50`.

ჩვეულებრივ ჯავშანზე სტუმრების რაოდენობა აუცილებელია და შეიძლება იყოს 1–100. „ჩვენთვის დაკავებულია“ მონაკვეთს ოჯახის გამოყენებისთვის იკავებს და სტუმრებისა და თანხების მნიშვნელობებს შენახვისას ნულზე აყენებს. „დადასტურებას ველოდებით“ მონაკვეთსაც დაკავებულად ითვლის, სანამ ჯავშანს არ შეცვლით ან გააუქმებთ.

საათები საქართველოს დროით აღირიცხება. თუ ერთი სტუმარი 12:00-ზე გადის, მეორე იმავე დღეს 15:00-ზე შეიძლება შემოვიდეს. აპი ჯავშნების უშუალო დროით გადაკვეთას ამოწმებს; დასუფთავებისთვის დამატებით შუალედს თავად ითვალისწინებთ.

### წერისას გაზიარება და საბოლოო შენახვა

ცვლილებები **მცირე ჯგუფებად, დაახლოებით 120 მილიწამიანი დაყოვნებით იგზავნება**, რასაც ემატება ქსელის დრო. უწყვეტი წერისასაც განახლებები რეგულარულად იგზავნება. სხვები ჩანაწერს ჯერ კიდევ შევსებისას ხედავენ. ბარათზე ჩანს, ვინ წერს; სრული ტექსტის სანახავად შესაბამისი ბარათი უნდა გაშალონ.

რედაქტორში განასხვავე ორი მდგომარეობა:

- **„ცვლილებები იგზავნება…“** — სერვერს ცვლილება ჯერ არ დაუდასტურებია.
- **„ცვლილებები სხვებთან გაზიარებულია“** — მონახაზი უკვე სერვერზეა და სხვა წევრებსაც ეგზავნება.

**ბოლოს მაინც დააჭირე „შენახვას“.** ამ დროს სერვერი ამოწმებს თარიღებს, საათებს, სტუმრების რაოდენობას, თანხებსა და გადამკვეთ ჯავშნებს. ავანსი სრულ ფასზე მეტი ვერ იქნება. წარმატებული შენახვის შემდეგ ჩანაწერი საბოლოო ჯავშნად ფიქსირდება და ისტორიაში ცვლილება ემატება.

გაზიარებული მონახაზი შეიძლება ჯერ არასრული იყოს. ის შენახულ ჯავშნს ავტომატურად არ ანაცვლებს; საბოლოო დასადასტურებლად „შენახვაა“ საჭირო. თუ ორი სხვადასხვა მონახაზი ერთსა და იმავე მონაკვეთს ეხება, პირველად შენახული ჯავშანი ჩაიწერება, მეორის შენახვაზე კი გადაკვეთის შეტყობინება გამოჩნდება.

### ერთდროული რედაქტირება

ერთი კონკრეტული ჯავშნის რედაქტირება ერთდროულად **ერთ ადამიანს შეუძლია**. დანარჩენები ცვლილებებს ხედავენ; მათთან ღილაკზე წერია „ახლა იწერება“. სხვადასხვა ჯავშნებზე პარალელურად მუშაობა შეიძლება.

რედაქტორის ჩვეულებრივი დახურვისას უკვე გაზიარებული ტექსტი **დაუმთავრებელ ჩანაწერად რჩება** და მოგვიანებით „გაგრძელებით“ იხსნება. „ცვლილებების გაუქმება“ მონახაზს შლის და მანამდე შენახულ ჯავშანს ტოვებს. კავშირის მოულოდნელი დაკარგვისას დროებითი დაკავება დაახლოებით ერთ წუთში იწურება, თუ გათავისუფლება უფრო ადრე არ მოხდა.

### ინტერნეტი და გაუზიარებელი ტექსტი

ყველას სჭირდება **იგივე ონლაინ მისამართი, ინტერნეტი და შესული ანგარიში**. გახსნილ და დაკავშირებულ აპში ცვლილებები პირდაპირ მოდის. თუ ტელეფონზე აპი დახურული ან შეჩერებულია, ხელახლა გახსნისას მიმდინარე ინფორმაცია ჩაიტვირთება. ამ ვერსიაში ფონური push შეტყობინებები არ იგზავნება.

კავშირის გაწყვეტისას გამოჩნდება გაფრთხილება და რედაქტირება დროებით შეჩერდება. უკვე სერვერზე გაზიარებული მონახაზები შენარჩუნებულია. **ჯერ გაუგზავნელი ტექსტი მხოლოდ იმ მომენტში გახსნილ ეკრანზე რჩება** — ბრაუზერის მუდმივ საცავში ის არ ინახება. გვერდის განახლებამ, აპის დახურვამ ან ტელეფონის მიერ მისი მეხსიერებიდან წაშლამ ეს ნაწილი შეიძლება დაკარგოს.

დაკავშირების აღდგენისას აპი თავიდან ითხოვს მიმდინარე მონახაზს. თუ გაუზიარებელი ტექსტი განსხვავდება, რედაქტორში გამოჩნდება მისი გადასაკოპირებელი ველი. შეადარე მიმდინარე ჩანაწერს, საჭირო ტექსტი შესაბამის ველში გადაიტანე და შეინახე. სერვის-ვორკერი აპის გარეგნობის ფაილებს ინახავს; პირადი ჯავშნების ოფლაინ ასლს არ ქმნის.

## ისტორია, გაუქმება და აღდგენა

**„ისტორიაში“** ჩანს, ვინ და როდის დაამატა, შეცვალა, გააუქმა ან აღადგინა ჯავშანი. „რა შეიცვალა“ ძველ და ახალ მნიშვნელობებს აჩვენებს. ეკრანზე იტვირთება ბოლო 200 მოქმედება; ექსპორტი სრულ შენახულ ისტორიას შეიცავს.

რედაქტორში **„ჯავშნის გაუქმება“** თარიღებს ათავისუფლებს, ჩანაწერი კი ისტორიაში რჩება. ეს თანხის ავტომატურ დაბრუნებას არ ასრულებს — სტუმართან ანგარიშსწორება თავად უნდა მოაგვაროთ.

გაუქმებული ჩანაწერისთვის ისტორიაში ხელმისაწვდომია **„ჯავშნის აღდგენა“**. დროის გადაკვეთა ხელახლა მოწმდება და თუ მონაკვეთს სხვა მოქმედი ჯავშანი იკავებს, აღდგენა დაიბლოკება. ეს ღილაკი გაუქმებულ ჯავშნს აღადგენს; ყველა ძველ რედაქციაზე დასაბრუნებელი საერთო მოქმედება ამ ვერსიას არ აქვს.

## პაროლების შეცვლა

ზედა ნაწილში დააჭირე შენი ანგარიშის წრეს და გახსენი **„ჩემი ანგარიში“**. საკუთარი პაროლის შესაცვლელად ჩაწერე მიმდინარე პაროლი, ახალი პაროლი და მისი გამეორება.

გიორგის შეუძლია დედას, ვეკოს ან ლიკას პაროლის შეცვლაც. აირჩიე შესაბამისი წევრი და დასადასტურებლად ჩაწერე **გიორგის საკუთარი მიმდინარე პაროლი**. სხვა წევრის ძველი პაროლი საჭირო არ არის. ცვლილება ამ მომხმარებლის სხვა მოწყობილობებზე არსებულ სესიებს ასრულებს და მათ ახალი პაროლით შესვლა მოუწევთ.

პაროლები სერვერზე შემოწმებისთვის გარდაქმნილი მნიშვნელობების სახით ინახება. სესიები დაცული cookie-ებით იმართება; შესვლისა და გამართვის მცდელობებზე სიხშირის შეზღუდვებია. გიორგის პაროლი საიმედოდ შეინახე — ამ ვერსიას ელფოსტით პაროლის აღდგენა არ აქვს და `SETUP_TOKEN` უკვე შექმნილ ანგარიშებს თავიდან არ გამართავს.

## სარეზერვო ასლი

გიორგის ანგარიშით გახსენი **„ჩემი ანგარიში“ → „სარეზერვო ასლის ჩამოტვირთვა“**. მიიღებ JSON ფაილს შენახული ჯავშნებით, გაუქმებული ჩანაწერებით, სერვერზე მიღებული მონახაზებითა და სრული ცვლილებების ისტორიით. შესვლის პაროლები და სესიები ფაილში არ შედის.

ასლი სტუმრების ინფორმაციას შეიცავს, ამიტომ პირად ადგილას შეინახე. **ამ ვერსიას JSON-ის უკან შემოტანის ღილაკი არ აქვს**; ასლიდან აღდგენა ცალკე ტექნიკურ ნაბიჯს მოითხოვს. სერვერის გასაღებისთვის ცალკე შეინახე თავდაპირველი `.dev.vars`.

## მოქმედი საიტის განახლება

როდესაც კოდში ცვლილებას შეიტან, იმავე საქაღალდიდან გაუშვი:

```bash
npm run deploy
```

ჩვეულებრივი კოდის განთავსება Worker-ში არსებულ secrets-ს ინარჩუნებს. **არ შექმნა ახალი `APP_SECRET` და არ შეცვალო საცავის კონფიგურაცია ჩვეულებრივი განახლებისას.** იგივე Worker-სა და საცავზე განთავსებისას ოჯახის ანგარიშები და ჯავშნები რჩება.

აპში განახლების შეტყობინების გამოჩენისას ჯერ რედაქტირება შეინახე, შემდეგ დააჭირე **„განახლებას“**. საჭიროების შემთხვევაში ინტერნეტთან კავშირის დროს აპი დახურე და ხელახლა გახსენი.

## კომპიუტერზე მოსინჯვა

პროექტის დაყენებისა და `.dev.vars`-ის შექმნის შემდეგ:

```bash
npm run dev
```

ტერმინალი გაჩვენებს ადგილობრივ მისამართს, ჩვეულებრივ `http://localhost:8787`. მისი მონაცემები ადგილობრივ საცავში ინახება და გამოქვეყნებული საიტისგან დამოუკიდებელია. ამიტომ პირველი გამართვაც ცალკე მოგიწევს: გამოიყენე ლოკალური `.dev.vars`-ის `SETUP_TOKEN` და სატესტო პაროლები.

ლოკალური ჯავშნები ონლაინ საიტზე ავტომატურად არ გადავა. ოჯახის წევრის ტელეფონზე `localhost` მისამართის გახსნა შენს კომპიუტერს არ ხსნის; საერთო გამოყენებისთვის მიეცი გამოქვეყნებული HTTPS მისამართი. ადგილობრივი სერვერის გასაჩერებლად ტერმინალში დააჭირე **Ctrl+C**.

ბრძანება ამოწმებს JavaScript-ის სინტაქსსა და ჯავშნის წესების ტესტებს. სერვერისა და სინქრონიზაციის ინტეგრაციული შემოწმება:

```bash
npm run test:integration
```

ინტეგრაციული ტესტი თვითონ უშვებს დროებით ადგილობრივ Wrangler სერვერს და სატესტო მონაცემებს იყენებს. ცალკე `npm run dev` წინასწარ ჩართვა არ სჭირდება. შემოწმებები შენს რეალურ ონლაინ მონაცემებს არ ცვლის.

### რა შემოწმდა ამ ვერსიაში

ადგილობრივად შესრულდა 9 ჯავშნის წესების ტესტი და 9 ინტეგრაციული სცენარი რეალურ Wrangler/workerd გარემოში, SQLite საცავითა და ორი WebSocket კავშირით. ინტეგრაციული runner მშობელ სცენარსაც ითვლის და ჯამში 10 ტესტს აჩვენებს.

შემოწმდა ავტორიზაცია და გამართვა, შენახვამდე მონახაზის გაზიარება, რედაქტირების დაკავება, გადამკვეთი ჯავშნის უარყოფა და გასვლის ზუსტ დროს ახალი შესვლა, სხვადასხვა ჯავშნის პარალელური რედაქტირება, არასწორი ავანსის უარყოფისას შენახული ჩანაწერის დაცვა, 10 000 ქართული სიმბოლოს მონახაზის დაბრუნება ხელახალი კავშირისას, გაუქმება და აღდგენის კონფლიქტი, JSON ექსპორტი, უცხო საიტიდან WebSocket კავშირის უარყოფა, ადმინისტრატორის მიერ პაროლის შეცვლა, საკუთარი პაროლის შეცვლისას სესიის განახლება და გამოსვლა.

Chromium 143 ბრაუზერში დამატებით შემოწმდა ორი დამოუკიდებელი ანგარიშის შესვლა, წერისას ტექსტისა და სტატუსის გაზიარება, დაგვიანებული პასუხისას შენახვის ლოდინი, ოჯახის გამოყენებისთვის დაკავებული ჯავშნის ხელახლა შენახვა, კავშირის გაწყვეტის შემდეგ გაუზიარებელი ტექსტის შენარჩუნება და 320/390 პიქსელის სიგანის ეკრანები. არ დაფიქსირდა გვერდის JavaScript შეცდომები; სერვის-ვორკერის ქეშში პირადი API პასუხები არ აღმოჩნდა. ეს შემოწმება ნამდვილ ტელეფონზე დაყენების ტესტს არ ანაცვლებს.

ასევე შესრულდა `wrangler deploy --dry-run`: განთავსების პაკეტი მომზადდა რეალური გამოქვეყნების გარეშე. **შენს Cloudflare ანგარიშზე საიტი ჯერ არ განთავსებულა.** ნამდვილ Android-სა და iPhone-ზე დაყენება უნდა შემოწმდეს შენი HTTPS მისამართის მიღების შემდეგ.

## Cloudflare-ის ხარჯები და ლიმიტები

ამ აპში ჩაშენებული AI სერვისი ან გარე ფასიანი მონაცემთა ბაზა არ არის. გაშვებული საიტის მოხმარება შენს Cloudflare ანგარიშზე აღირიცხება.

Cloudflare-ის მიმდინარე დოკუმენტაციით, **Workers Free გეგმაზე SQLite Durable Objects ხელმისაწვდომია**; სწორედ ეს საცავია პროექტში გამოყენებული. Free გეგმას აქვს მოთხოვნების, გამოთვლის, წაკითხვის, ჩაწერისა და შენახვის ლიმიტები. რესურსები შენს გეგმასა და ანგარიშის სხვა პროექტებთან ერთად გადაამოწმე. ეს ნებისმიერი დატვირთვით ან სამუდამოდ უფასო მომსახურების გარანტიას არ ნიშნავს. [Durable Objects-ის ფასი და ლიმიტები](https://developers.cloudflare.com/durable-objects/platform/pricing/).

სტატიკური ფაილების მიწოდებისა და Worker API მოთხოვნების აღრიცხვა განსხვავდება; ავტორიზაცია და საერთო განახლებები სერვერის რესურსებს იყენებს. [Static Assets-ის აღრიცხვა](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/).

WebSocket Hibernation კავშირებს უმოქმედობისას ნაკლები გამოთვლითი დანახარჯით ინარჩუნებს. რეალური შეტყობინებები და SQLite ჩანაწერები მაინც აღირიცხება. [Cloudflare WebSockets და Hibernation](https://developers.cloudflare.com/durable-objects/best-practices/websockets/).
