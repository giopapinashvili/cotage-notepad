# აგარაკის ჯავშნები

ქართული ჯავშნების რვეული აგარაკისთვის: https://javshnebi.pages.dev

- საიტი ცარიელი რვეულით იხსნება. პირველი ჯავშნის დამატებისას სერვერზე იქმნება ამ ბრაუზერის რვეული (ექაუნთი ელფოსტის გარეშე), რომელსაც მხოლოდ ამ ბრაუზერის HttpOnly ქუქი ხსნის. სხვა ბრაუზერი მას ვერ ხედავს.
- რეგისტრაცია (ელფოსტა/პაროლი ან Google) იმავე ექაუნთს ამატებს ელფოსტას, ჯავშნები ადგილზე რჩება. არსებულ ექაუნთში შესვლისას ბრაუზერის ჯავშნების გადმოტანა შეიძლება; თარიღით გადაფარული ჯავშნები არ გადმოდის.
- რეგისტრირებულ ექაუნთში ოჯახის ყველა წევრი თავის სახელს ირჩევს ან ამატებს. ჯავშანზე ჩანს, ვინ შექმნა და ვინ შეცვალა, ისტორიაში კი ყველა ცვლილების ავტორი. ცვლილებები ღია მოწყობილობებს მაშინვე ეზიარება (WebSocket).
- 180 დღე გამოუყენებელი დაურეგისტრირებელი რვეულები თავად იშლება.

## აგებულება

| ნაწილი | სად | რას აკეთებს |
| --- | --- | --- |
| `src/worker.js` + `public/` | Worker `cotage-notepad` | საიტის ფაილები, API, ექაუნთები, Google OAuth, WebSocket-ის გადაცემა |
| `src/accounts.js` | Durable Object `AccountsStore` (ერთი) | ექაუნთები, სახელები, სესიები, ლიმიტები, დასუფთავება |
| `src/notebook.js` | Durable Object `FamilyNotebook` (თითო ექაუნთზე) | ჯავშნები, მონახაზები, ისტორია, ცოცხალი სინქრონიზაცია |
| `pages-site/` | Pages `javshnebi` | „შესასვლელი კარი“: ყველა მოთხოვნას (WebSocket-საც) service binding-ით გადასცემს Worker-ს |

Pages პროექტში მხოლოდ გადამგზავნი სკრიპტია, ამიტომ განახლებისთვის საკმარისია Worker-ის ატვირთვა (GitHub-იდან ან სკრიპტით). `PUBLIC_URL` secret-ად ინახება მას შემდეგ, რაც Pages მისამართი შეიქმნება; მერე Worker-ის workers.dev მისამართი 302-ით გადადის მასზე. პაროლი ბრაუზერში იჭიმება (PBKDF2, 150 000) და სერვერზე კიდევ ერთხელ (PBKDF2, 20 000, შემთხვევითი მარილით).

Secrets (Worker-ზე): `PUBLIC_URL`, სურვილისამებრ `GOOGLE_CLIENT_ID` და `GOOGLE_CLIENT_SECRET`. Google-ის redirect URI: `https://javshnebi.pages.dev/auth/google/callback`. იგივე Google client შეკვეთების საიტთან ერთად გამოიყენება.

`wrangler.jsonc`-ში Worker-ის სახელი და Durable Object-ების მიგრაციები არ შეცვალო.

## ატვირთვა

- GitHub-ზე `main`-ში ატვირთვა Worker-ს ავტომატურად აახლებს, თუ Cloudflare-ში Git კავშირი ჩართულია.
- `upload-to-cloudflare.cmd` (ან `npm ci && npm run deploy`) ერთხელ მაინც გაუშვი: ქმნის Pages მისამართს, ინახავს Google-ის გასაღებებს `deployment-secrets.json`-ში და რთავს ძველი მისამართის გადამისამართებას. დეტალები: [START-HERE.txt](START-HERE.txt).

## ლოკალური შემოწმება

```sh
npm ci
npm run dev                # http://localhost:8787
npm run check              # სინტაქსი და დომენის ტესტები
npm run test:integration   # სრული ტესტი დროებით სერვერზე
```

`COTTAGE_URL=http://127.0.0.1:8788 npm run test:integration` იგივე ტესტს უკვე გაშვებულ სერვერზე უშვებს, მაგალითად `wrangler pages dev`-ის გავლით.
